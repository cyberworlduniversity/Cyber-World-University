# Contributing to Cyber World University

Thank you for your interest in contributing to Cyber World University (CWU).

CWU welcomes contributions that improve cybersecurity education, software quality, security, accessibility, documentation, testing, and maintainability.

## Before You Start

- Read the README.
- Check existing issues and pull requests before starting duplicate work.
- For security vulnerabilities, do **not** open a public issue. Follow [SECURITY.md](SECURITY.md).
- Keep changes focused and explain why the change is needed.

## Types of Contributions

Examples include:

- Bug fixes
- Security improvements
- Test coverage
- Documentation
- Accessibility improvements
- UI improvements
- Educational content
- Course and lesson improvements
- Quiz and examination improvements
- Performance improvements
- Developer tooling
- Refactoring that improves maintainability

## Development Workflow

1. Fork the repository or create a development branch when appropriate.
2. Make your changes.
3. Keep secrets and credentials out of the repository.
4. Test the affected functionality.
5. Review your changes for security, accessibility, and unintended side effects.
6. Update documentation when necessary.
7. Open a pull request with a clear description.

## Pull Request Guidelines

A good pull request should explain:

- What changed
- Why it changed
- How it was tested
- Any security considerations
- Any database or environment-variable changes
- Any known limitations

Keep pull requests reasonably focused so they can be reviewed effectively.

## Commit Guidelines

Use clear commit messages that describe the change.

Examples:

- `fix: validate quiz submission input`
- `feat: add course progress tracking`
- `docs: improve contributor guide`
- `security: strengthen authorization checks`

## Educational Content

Cybersecurity educational content should be accurate, responsible, and appropriate for learners. Do not add instructions intended to facilitate unauthorized access, credential theft, malware deployment, or other harmful activity.

When practical, provide safe lab environments, defensive explanations, and clearly defined authorized-use boundaries.

## Questions

For general project questions, use the repository's public issue or discussion mechanisms when available.
