# Security Policy

Security is a core consideration for Cyber World University (CWU).

## Supported Project

Security reports should identify the affected component, a clear description of the issue, the potential impact, and enough information to reproduce the issue safely.

## Reporting a Vulnerability

Please **do not publicly disclose an unpatched security vulnerability through a GitHub issue, pull request, or discussion**.

Use GitHub's private vulnerability reporting/security advisory mechanism when it is available for this repository. If private reporting is unavailable, contact the project maintainer through an appropriate private channel before public disclosure.

## What to Include

Please provide:

- A short description of the vulnerability
- Affected file, endpoint, or feature
- Steps to reproduce
- Expected behavior
- Actual behavior
- Security impact
- Relevant logs or screenshots, with secrets and personal information removed
- A suggested mitigation, if known

Please avoid testing against systems or accounts that you do not own or have explicit authorization to test.

## Sensitive Information

Never include passwords, API keys, database credentials, session secrets, private tokens, or personal information in a security report.

If sensitive information was accidentally committed, report it privately so the project can assess the exposure and rotate affected credentials.

## Responsible Disclosure

Please allow the maintainers reasonable time to investigate and address a reported vulnerability before publicly disclosing technical details.

Thank you for helping keep CWU and its users safer.
